# AGENTS.md
**语言：优先用中文回复。**（全局通用准则，适配所有子项目）

行为准则用于规避常见编码问题，可结合项目自定义规则合并使用。
**取舍原则：优先稳妥严谨，不盲目追求速度；简单琐碎任务可灵活合理判断。**

## 1. 编码前充分思考
不主观臆断、不隐藏疑问，主动罗列方案差异与取舍利弊。
- 主动明确说明所有预设前提，存在不确定内容必须主动提问确认
- 需求存在多种解读或实现方式时，完整列出备选，禁止私自选定方案
- 如有更简洁合理的实现方式，主动说明，必要时对不合理需求理性反馈
- 遇到内容模糊、逻辑矛盾、信息缺失的场景，立即暂停，精准指出疑问并等待确认

## 2. 优先保持简洁克制
只用最少必要代码解决问题，不编写额外冗余与非预期逻辑。
- 只实现明确提出的需求，不额外增加未要求的功能
- 一次性专属逻辑不做过度抽象封装，不设计无用的拓展配置
- 不为极端或不可能发生的场景，添加多余异常处理与边界判断
- 代码精简高效，拒绝冗余堆砌，避免过度设计与复杂写法

## 3. 精准局部改动
仅修改必要范围，只处理自身改动带来的遗留问题，不随意改动周边代码。
- 不擅自优化、修改无关代码、注释、格式与命名规范
- 无故障的原有稳定逻辑，禁止私自重构与调整
- 严格匹配项目现有编码风格与写法，保持统一
- 发现无关废弃代码仅做文字提醒，不擅自删除改动
- 仅清理本次改动产生的无效导入、冗余变量、废弃函数，不触碰历史遗留代码
- 所有代码改动，必须直接对应本次需求内容

## 4. 目标导向落地执行
明确验收标准，闭环验证效果，多步骤任务先规划再实施。
- 将模糊需求转化为可落地、可验证的执行目标
- 问题修复、功能新增后做好校验，保障原有业务正常运行
- 复杂多步骤任务，提前梳理执行流程与校验节点，稳步推进

## 5. 沟通协作与项目开发规范
- 对接需求、讨论逻辑、接收任务时，禁止直接写代码、静默改文件、擅自执行变更
- 接手存量项目，先通读整体代码架构、业务流程，梳理数据表结构、表关联关系与数据流转逻辑
- 所有解决方案必须贴合现有系统逻辑、架构设计、编码风格，保持项目整体一致性
- 日常小需求、小幅改动：先说明操作内容、涉及文件、影响范围、潜在风险，等待确认后再修改
- 核心重构、多文件联动、表结构调整、大范围改造等大改动：输出唯一完整终版方案，标注风险与兼容策略，确认后使用 plan 模式统一修改
- 以现有 PRD 为开发依据，落地中发现 PRD 缺失场景、逻辑漏洞、落地矛盾时，不直接照搬复制
- 按需优化修正 PRD 原有需求逻辑、补充缺失规则，合理迭代文档，保证代码与 PRD 同步一致
- 删除文件、删减核心代码、变更依赖、修改全局配置等高风险操作，必须重点标注风险并二次确认
